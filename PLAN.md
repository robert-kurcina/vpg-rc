## Deferred post-release performance work (author requested; not release gates)

1. Profile actual browser and headless workloads across representative missions, including input latency, long tasks, pan/zoom frame times, memory, AI decision time and batch throughput. Establish measured bottlenecks before changing architecture.
2. Evaluate Web Workers for expensive AI decisions and independent simulation jobs. Keep JavaScript engine authoritative: validate candidate actions on the main thread, bind requests to current state, discard stale results, preserve committed RNG, cancellation and exact replay. Maintain a JavaScript fallback. No backend required.
3. Optimize measured JavaScript hot paths first: immutable movement graph reuse, state-scoped ZOC/supply indexes, redundant allocations and search. Accept only demonstrated gains with deterministic equivalence and save compatibility.
4. Prototype selective single-threaded WebAssembly (e.g. Rust) kernels for pathfinding, graph traversal, ZOC, supply and AI evaluation using compact numerical inputs and batched calls. Benchmark end-to-end including marshaling and startup; retain JS fallback and do not fork rules. Independent workers preferred over shared-memory WASM because GitHub Pages cross-origin isolation is not assumed.
5. Evaluate WebGL only if measured SVG pan/zoom/rendering latency warrants it. Preserve approved map/counter geometry, layering, hit targets, accessibility and touch behavior; retain SVG unless a prototype demonstrates a meaningful benefit. One shared renderer, not scenario forks.

These are ordered investigation ideas, not new release deliverables or guaranteed speedups. Complete the current six priorities first. Unified grand campaign remains absolute last, after all other approved work.
