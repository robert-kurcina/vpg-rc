# Checkpoint 205 / v439 — Corrected terrain bitmap palette experiment

## Root cause corrected

The previous v438 experiment changed only `PALETTES.generic` in the shared renderer. All five historical map profiles provide their own `renderOptions.palette`, which overrides the generic fallback. Additionally, the original full-opacity terrain bitmap textures were drawn over the fill. Consequently the requested shades were not actually applied to the five maps. v438's description of a completed visual palette change was inaccurate.

## Actual correction

The requested shades are applied to **both** the map profile fill values and new alternate copies of the raster textures:

| Terrain | Opaque target | Recolored bitmap |
|---|---|---|
| Open | `#dcd4c9ff` | `supplied_assets/flat/terrain-open-v439.png` |
| Forest | `#727f61ff` | `supplied_assets/flat/terrain-forest-v439.png` |
| Swamp | `#616f6fff` | `supplied_assets/flat/terrain-swamp-v439.png` |

The Open input `dcd4c9f` was normalized to the eight-digit opaque `#dcd4c9ff`.

Bitmap processing in `scripts/recolor-terrain-bitmap-v439.py` moves each original tile's CIELAB average toward the chosen target while preserving local luminance and chroma variation (foliage, relief and pools). Raster alpha masks and dimensions are **identical** to the originals; the original `terrain-*.png` assets are not overwritten. The new variants remain an experiment and have not been accepted as the permanent art baseline.

`maps/registry.json` now carries the three colors in **every** scenario's presentation palette; the shared `core/presentation.js` uses the variant textures only for those three kinds. `core/native_browser_view.js` and `scripts/export-campaign-maps.js` both now derive their bitmap references from this same `P.textures()` mapping. The old 22% pale-green Open overlay was disabled in the presentation defaults for a more faithful beige target. No per-scenario renderer was introduced.

## Verification and limitations

- All five map SVG+PNG exports regenerated by the actual shared map renderer and Inkscape; `exports/manifest.json` contains the current hashes. Zero map validation errors.
- `tests/terrain-bitmap-palette-v439.test.js`: **61 assertions** for variant bitmap hashes, target means, shared paths, per-game palette entries and SVG-embedded assets.
- `tests/terrain-bitmap-browser-v439.py`: Chromium in-memory real shared-engine Kiev SVG scene rendered and decoded the three new variant PNGs, with no page errors.
- Direct HTTP localhost Chromium gameplay navigation was blocked by the execution environment (`ERR_BLOCKED_BY_ADMINISTRATOR`); **full browser-game smoke is not claimed**.
- Kiev source-reviewed movement (**2,949 assertions**), opening preflight (**289 assertions**), layout (**180 assertions**), Soviet 4th Mechanized restriction (**24 assertions**) and user marker corrections passed.
- `rules/audit/terrain-palette-preservation-v439.json` certifies the original bitmap files, map source files and gameplay rules unchanged from v438. Only the presentation/asset-routing code and `maps/registry.json` were changed in those categories.
- The legacy `scripts/verify-campaign-maps.js` PNG hash baseline targets a superseded visual profile and is not applicable to intentional new bitmap colors. It is not reported as passing.
