# Battle for Moscow — Configured objective advance policy (Checkpoint 174, v408)

## Scope

An *opt-in* third native AI policy `objective-advance-v1` is exposed in the existing Battle for Moscow shared-engine browser preview. It extends the earlier objective-guard strategy, retaining its objective-hex movement/defensive replacement choices and adding an advance decision **after** a combat die is committed. The shared rules engine (`core/engine.js`), single original B4M CRT, official source counter art, all five accepted v373 no-shadow map exports, and `games/battle-for-moscow/game.json` production legacy selector are unchanged.

When a committed combat targets a source-configured control objective not already owned by the acting faction, and the read-only authoritative CRT preview reports an advance-capable result without an applicable major-city DR hold, this policy omits `advanceId`. That lets the shared combat transaction choose the existing source-configured default surviving attacker **if the target actually becomes vacant**. It does not itself determine retreat, enemy survival, eligible advance unit, ownership, or victory. For all other battles it retains the existing explicit `advanceId:'none'`. Automatic no-die NE requests submit **empty options**, avoiding the invalid `advanceId` key. All existing baseline and `objective-guard-v1` choices remain unchanged.

### Release boundaries

This is **not** an active B4M production cutover. The default browser still opens `legacy/index.html`; shared-native B4M remains opt-in. The native policy is deliberately simple: it does not search multiple plies or guarantee capture/wins, and currently enters a non-objective defender hex only when its original tactical policy chooses it. Tactical superiority requires separate benchmarked evaluation. Tournament reserve-coordinate conflict `0608/0609` and `0803/0804`, original Oberlabs destination-set observation, independent hosted-browser acceptance, and broader manual gameplay coverage remain outstanding. Other three historical campaigns have not been certified. Oberlabs UX parity remains deferred until gameplay completion.
